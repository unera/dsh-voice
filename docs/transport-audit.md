# Аудит голосового транспорта

Что происходит от нажатия кнопки до звука из динамика. Всё ниже — по коду на
13.11.2026: клиент `dsh-node-client-android` 0.10.22, хост `dsh-voice` 0.1.1,
`dsh-nodes` 0.3.31.

## Отказы и что слышит человек

| когда | код | что говорит телефон |
|---|---|---|
| запись не пришла за 12 с | `voice_timeout` | «Не услышал попробуй ещё раз.» |
| файл не забрался | — | «Не смог забрать запись.» |
| расшифровка пустая | — | «Не расслышал, повтори пожалуйста.» |
| доставка в сессию не удалась | — | «Не смог передать запрос.» |

## Свойства, которые важны для аудита

- **Нажатие = обещание ответа.** Нажатия встают в очередь по узлу; отброшенных
  нет (иначе терялся `want`, а запись парковалась до следующего нажатия).
- **Телефон автономен.** `want` можно не доставить — запись всё равно легла
  файлом и уйдёт следующей командой `record`.
- **Таймаут записи 12 с**, а не 45: 45 с — это было человеко-время в очереди
  команд, из-за него ответы отставали.
- **`flushAround` на голосовых командах не объявляется** — барьер выполнялся
  только на пустом пуле и запирал очередь на всю длину записи.
- **Сессия одна на устройство**, номер живёт в `cache/voice/sessions.json`.
- **Транспорт известен хосту**: `transport: nodes`, `botId: nodes_<id>`, поэтому
  правила ассистентов могут целиться в конкретный телефон.

## Дыры, которые видны при аудите

1. **Синтез делается и выбрасывается.** Аудио из п.19 удаляется, человек слышит
   системный TTS телефона (п.20). Нужен `voice.play`, чтобы звучал наш голос и
   работала настройка темпа/голоса.
2. **`want` не идемпотентен.** Двойное нажатие в момент, когда запись уже
   идёт, создаст второе нажатие в очереди; второй `record` вернёт ту же
   запаркованную запись и получит пустую расшифровку → «Не расслышал».
   Нужен отпечаток нажатия (`want.id`) и дедупликация.
3. **Нет отмены «я передумал»**: `voice.stop` есть только для речи.
4. **Сессия создаётся без рабочей папки и пресета** (`create({sessionId})`) —
   голосовой чат не знает о workspace.
5. **Нет ограничения на длину ответа**: `# say` ограничен только промптом,
   длинный ответ читается целиком.
6. **Нет метрик**: ни длительности записи, ни времени до первого звука, ни
   числа отказов — по логу видно только факты, а не тайминги.
